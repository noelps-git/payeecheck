The Structural Gap

The UK mandated payee name verification in 2020. India hasn't yet.

UPI routes money via account number and VPA — the name you see is a display label only. There's no mandatory cross-check that the name the payer typed matches the account holder on file. PayeeCheck addresses this gap.

🇬🇧 United Kingdom

Confirmation of Payee (CoP)

  • Mandated by PSR in 2020 for all major UK banks
  • Real-time name verification at point of payment — mandatory
  • PSR evaluation report (2022): ~17% reduction in APP fraud in year one
  • MAST (Mule Account Sharing Tool) — consortium cross-bank mule flagging
VS
🇮🇳 India — UPI / NPCI

No Mandatory Payee Name Verification

  • 17B+ transactions/month — zero structural payee name check
  • VPA name is a display string only — routing is by account number
  • An attacker can register any display name on any VPA
  • RBI has proposed a CoP-equivalent — implementation timeline pending

Signal Architecture

Seven signal modules. Each with progressive depth.

Each module outputs a grounded assertion with a specific numerical value and threshold. Every verdict is fully traceable through a three-layer attribution record — designed to meet RBI Model Risk Management interpretability requirements.

01
🔤
Name Matching
L1 → L6
Jaro-Winkler → phonetic → TF-IDF char n-grams → sentence embeddings → Siamese fine-tune → graph entity resolution. Handles Indian transliteration, abbreviations, and entity type mismatch.
02
🎭
Look-alike VPA
L1 → L5
Protected Brand Token Registry (NPCI-style, zero ML) catches the 'paytm.support@axl' pattern that string distance cannot. Highest leverage per engineering cost.
03
🕳️
Mule Database
L1 → L4
Static flag lookup → velocity scoring (fan-in, pass-through speed, balance volatility) → consortium shared DB (MAST-modelled) → graph-based ring propagation.
04
📱
Behavioural SDK
L1 → L4
Client-side: paste vs type, app-switch timing chain (cross-app copy from SMS), device fingerprint, per-user z-score baseline. Fires before any server-side check.
05
⚡
VPA Velocity Engine
L1 → L4
Rolling window velocity (24h/7d/30d), amount-ratio scoring, salary-cycle-aware seasonal z-score, linear trend early-warning forecast. Detects mules before any report is filed.
06
🚫
Sanctions Screen
Fuzzy Match
PEP and sanctions list fuzzy matching on payee name. Hard block at threshold — overrides all other signals. Illustrative seed lists in sandbox; production requires OFAC/UN/domestic integration.
07
🕸️
GAT Ring Detector
PyTorch Geometric
Edge-feature Graph Attention Network (GATConv, edge_dim). Trained on 636-node synthetic graph. Catches fraud rings via shared mobile/device attribute propagation, not just individual flags.
08
🔄
Transaction Graph GNN
PROPOSED
Money-flow edges (who paid whom, amount, frequency). LineMVGNN-inspired pass-through score. Next in the development queue — not yet built.

Technical Underpinnings

The architecture, cited honestly.

Edge-Feature Graph Attention Network

The GAT ring detector uses PyTorch Geometric's GATConv(edge_dim=…) — edge features concatenated directly into the attention coefficient computation:

α_vu = softmax(LeakyReLU(aᵀ[Wh_v ‖ Wh_u ‖ e_vu]))

Directly informed by SCAFDS (Uddin, 2026) Stage 3 architecture — the fraud co-occurrence edge-feature formulation applied to mule ring detection rather than interbank forensics. Ablation result: 95.6% vs 88.9% precision, confirming edge features carry real signal.

Three-Layer Attribution Record

  • Layer 1 — Transaction: How was this initiated? Paste vs type, timing, device fingerprint, first-time payee flag.
  • Layer 2 — Payee Network: What do we know about the destination? VPA age, velocity, mule flags, name score, lookalike signals, GAT ring score.
  • Layer 3 — Temporal: How does this compare to the payer's own history? Amount vs average, time-of-day, SIM change proximity.

Every signal fires a grounded assertion with a specific numerical value and threshold — designed to meet RBI Draft Model Risk Management Guidelines (2023) interpretability requirements.

Five Signal Playbooks — 121 Pages

  • Name Matching: L1–L6, 47 pages. Jaro-Winkler through graph entity resolution.
  • Look-alike VPA Detection: L1–L5, 21 pages. NPCI-style Brand Token Registry.
  • Mule Account Database: L1–L4, 18 pages. MAST-modelled consortium architecture.
  • Behavioural Signal SDK: L1–L4, 18 pages. Client-side JS + Android Kotlin code.
  • VPA Age + Velocity Engine: L1–L4, 17 pages. Salary-cycle-aware anomaly detection.

Real Bugs Found and Fixed

  • Dataset inconsistency: mule_flagged set independently from mule_flag_count — capped recall at 47%. Fixed: mule_flagged = mule_flag_count > 0. Recall jumped to 82.6%.
  • Vacuous GAT ablation: Non-overlapping fraud/clean feature ranges made the ablation meaningless. Fixed by overlapping ranges — produced a real 6.7pp edge-feature contribution.
  • Idempotency bug: FastAPI static decorator silently overrode dynamic status codes. Fixed via explicit JSONResponse.
  • IP whitelist bypass: testclient exemption defeated the security control entirely. Removed and verified.
⚠ Honest Framing

All benchmark numbers (Precision 1.00, Recall 82.6%, AUPRC ~0.996) are from rule-generated synthetic data on 1,000 transactions. They measure whether the pipeline correctly recovers patterns deliberately encoded in the generator — not real-world accuracy on live bank data. This framing mirrors how SCAFDS (Uddin, 2026) itself frames its synthetic Track B evaluation. Real-world calibration requires labelled outcomes from a production bank deployment.

Regulatory Context

The global direction is clear. India is next.

🇬🇧
United Kingdom
Live since 2020
  • Confirmation of Payee mandated by PSR for all major UK banks
  • PSR evaluation (2022): ~17% reduction in APP fraud in year one
  • MAST — Mule Account Sharing Tool, consortium cross-bank flagging operated by Stop Scams UK
  • Extended to all UK PSPs by 2024, not just the original six
🇮🇳
India — UPI / NPCI
Proposed
  • RBI has proposed a CoP-equivalent for UPI — implementation timeline pending
  • RBI Draft Model Risk Management Guidelines (2023) require interpretable, auditable AI in BFSI
  • 17B+ UPI transactions/month — zero mandatory name verification today
  • PayeeCheck is a working proof-of-concept of what this regulation will require
🇪🇺
European Union
Mandated Oct 2025
  • Verification of Payee (VoP) entered into force October 2025 for all SEPA Credit Transfer participants
  • Requires real-time payee name-to-IBAN verification before any transfer is processed
  • EU follows UK's lead — both validate the CoP model at regulatory scale
  • Sets global precedent: name verification is a baseline expectation, not a premium feature
